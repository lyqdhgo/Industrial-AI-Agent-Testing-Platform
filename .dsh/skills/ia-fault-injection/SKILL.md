# 工业故障注入方法论

> 来源说明：本次输入附件未包含独立的 `ia-fault-injection` 正文（其中一份文件与
> `ia-mechanism-constraint` 重复）。本文件依据 `AGENTS.md` R3/R4、附件
> `ia-scenario-design` §3 的物理完整性要求补齐，不新增任何工艺阈值。

## 0. 第一原则

**故障注入是物理过程，不是给数据贴标签。**

每一个注入器都必须输出三类东西：

1. 注入参数（类型、位号、起始时刻、持续时长、幅值/速率、seed）；
2. 故障前后的真实过程状态与测量值；
3. 可被独立检查的物理特征（斜率、残差、偏差、质量位、时间戳缺口）。

只改显示值而不改被控对象响应，或者瞬间跳变到目标值，均视为**无效注入**，用例作废。

---

## 1. 六类标准故障

| 故障 | 作用对象 | 必须体现的物理特征 | 禁止做法 |
|---|---|---|---|
| `super_temperature` | 工艺真实温度 | 一阶热惯性 + 传输延迟，升温速率受限，联锁按真实值动作 | 瞬时跳到目标温度；只改显示值 |
| `over_pressure` | 工艺真实压力 | 压力按自身时间常数缓慢爬升；与温度响应存在相位差 | 与温度完全同相；无上下游影响 |
| `sensor_drift` | 测量通道 | 真实值稳定，测量值单向偏移且单调累积，偏差可复现 | 真实值同时漂移；来回抖动冒充漂移 |
| `valve_sticking` | 执行机构 | 指令变化而阀位反馈不跟随，残差持续；流量响应与阀位一致 | 阀门无反馈；只改流量不改阀位 |
| `sensor_disconnect` | 测量通道 | 冻结值 / 超量程 / `BAD` 质量位，保留最后有效时间戳 | 将值置 0（与真实零值混淆） |
| `network_jitter` | 传输链路 | 延迟、丢包、乱序、时间戳不连续；真实过程不受影响 | 只延迟而不改到达时间/时间戳 |

## 2. 注入器接口

```python
class FaultInjector(Protocol):
    fault_id: str
    target_tag: str
    start_s: float
    duration_s: float

    def effect(self, state: ProcessState, t_s: float) -> ProcessState: ...
    def measurement(self, measured: float, truth: float, t_s: float,
                    quality: Quality) -> tuple[float, Quality, float]: ...
```

- `effect` 只作用于**真实过程状态**，且必须受速率上限与时间常数约束。
- `measurement` 只作用于**测量通道**，不得反向伪造真实状态。
- 每次调用必须只依赖 `(case_seed, fault_id, tag, t_s)` 推导出的确定性随机源。
- 注入器不得读取用例的期望结论，也不得直接生成 Agent 响应。

## 3. 物理完整性门禁

每个故障用例在进入评测前，必须通过以下自动检查：

1. **响应性**：注入窗口内，目标测点特征量变化超过噪声带；
2. **物理方向**：超温只能升温，超压只能升压，漂移保持单向；
3. **速率约束**：温度/压力变化速率不超过 `mechanisms.json` 声明的上限；
4. **非目标位号隔离**：除工艺耦合外，不得出现无解释的同步跳变；
5. **故障终止可恢复**：故障结束后真实状态按动态模型恢复，不得永久锁死；
6. **断线可识别**：质量位/超量程/冻结特征至少命中一项；
7. **抖动可识别**：时间戳缺口或乱序在产物中可复查；
8. **联锁独立**：SIS 只使用独立安全测点/真实状态，不读取被漂移的显示值。

任一门禁失败 → 用例标记 `invalid_injection`，不得用于指标计算。

---

## 4. 产物要求

每个故障用例的 artifact 必须包含：

- `case.yaml`：注入参数与 seed；
- `series.csv`：测量值、真实值、质量位、采样时刻、到达时刻；
- `injection.json`：故障物理特征检查结果；
- `responses/`：Agent 原始请求与响应；
- `verdict.json`：判定过程与缺陷等级。

报告中不得只给“注入了超温”，必须给出可下钻的物理证据。

## 5. 与上下游 Skill 的接口

- 上游：`ia-scenario-design` 负责选择用例类别、时间轴与期望断言；
- 本 Skill：负责把故障计划落地为满足物理约束的时序；
- 下游：`ia-mechanism-constraint` 校验 Agent 建议与结论；
- 下游：`ia-interlock-verify` 校验 SIS 动作与越权；
- 下游：`ia-eval-metrics` 只用通过注入门禁的用例计算指标。

## 6. 自检清单

- [ ] 每个故障都有独立注入器与单测
- [ ] 故障作用于真实过程还是测量通道，语义清晰
- [ ] 所有随机量使用派生 seed，并记录到产物
- [ ] 超温/超压有速率上限与惯性，不是阶跃
- [ ] 漂移是单向偏差，不是真实值同漂
- [ ] 卡涩残差持续存在，且流量响应一致
- [ ] 断线用质量位/冻结/超量程表达，不用 0 值
- [ ] 抖动改变时间戳连续性与到达顺序
- [ ] 注入后自动执行物理完整性门禁
- [ ] 无效注入用例被排除出指标分母
